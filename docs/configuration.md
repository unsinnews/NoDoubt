# 配置格式与参数

NoDoubt 使用带版本的应用配置 JSON：`schemaVersion: 1`、服务列表 `providers` 和应用扩展 `nodoubt`。GUI 和文件操作通过同一解析、验证、存储流程。入口是「我的 → 模型服务」，其中「解题模型」管理用途，「配置文件」管理本地与远程文件。

## 基础结构

```json
{
  "schemaVersion": 1,
  "providers": {
    "my-service": {
      "name": "我的服务",
      "api": "openai-responses",
      "baseUrl": "https://api.openai.com/v1",
      "apiKey": "$MY_API_KEY",
      "models": [
        { "id": "your-model-id", "name": "主模型" }
      ]
    }
  },
  "nodoubt": {
    "name": "我的配置",
    "variables": {},
    "channels": {
      "my-service": {
        "enabled": true,
        "parameters": {},
        "models": {}
      }
    },
    "bindings": {
      "OCR": { "entries": [], "selected": null },
      "FAST": { "entries": [], "selected": null },
      "DEEP": { "entries": [], "selected": null }
    }
  }
}
```

导入后在「我的 → 模型服务 → 配置文件 → 变量映射」添加名称 MY_API_KEY 并填写实际值，或在服务详情直接替换 API Key；再到「解题模型」绑定用途。变量值和敏感 Header 会转成凭据引用并加密存储。已保存的 API Key 不回填显示，输入新值会替换；清除凭据使用「清除密钥」。

同一协议可有多个 provider ID。模型 ID 在渠道内唯一，用途通过 `{"channelId":"my-service","modelId":"your-model-id"}` 引用，避免不同渠道同名模型混淆。

## GUI 的保存边界

- 服务名称、协议、地址、请求头、模型和参数都先进入服务草稿；在服务详情右上角点击「保存」统一生效。
- 模型详情和参数页返回时保留草稿；离开未保存的服务会显示继续编辑、保存并返回、放弃更改的选项。旋转设备会在当前进程内保留草稿，进程被系统终止后的草稿恢复不作保证。
- 「测试连接」和「添加模型 → 从服务获取」使用当前草稿，无需先保存。测试需要选定模型；目录没有返回模型时仍可「手动添加」。
- 「模型目录 URL」为空时使用协议默认目录。自定义跨域目录不会收到渠道密钥与请求头。
- 「模型详情 → 高级设置 → 模型容量」里的上下文窗口、最大输出属于元数据；实际请求参数在「请求参数」中显式启用。Anthropic 必需输出上限的后备规则见下文。
- 用途绑定、主题偏好、变量映射和配置集切换立即保存。每种用途先使用默认项，再按候选顺序尝试其余项；模型和渠道被删除后，对应用途引用同步移除。

## 思考设置与参数三态

需要长期保存的思考参数在具体模型的常规详情页配置，使用「默认 / 修改」。「默认」不额外发送思考参数；选择「修改」后填写该模型的强度、预算等协议对应选项，并随服务草稿一起保存。Anthropic 手动开启思考时需填写至少 1024 的预算。解答页也可临时调整当前题、当前模式的思考设置，不写回这里的配置。

响应中的思考内容按服务实际返回展示。即使模型保持「默认」，极速解题和深度思考两种模式收到思考内容后都会显示可折叠思考区，默认展开。没有返回思考内容时，不显示空的思考区。

渠道中的思考设置不会成为模型默认值。导入旧文件时，渠道的 `thinking`、`reasoning`、`output_config.effort` 等思考字段会被忽略并显示提示；这一规则也覆盖对象、点路径及渠道 `extraBody`。模型自己的显式参数和 `extraBody` 仍可配置思考。旧模型的思考 `INHERIT`、`OMIT` 或未设置都不会发送渠道思考字段。

`nodoubt.channels.<id>.parameters` 保存普通渠道参数，`nodoubt.channels.<id>.models.<modelId>.parameters` 保存模型参数。下面是普通参数的三态示例：

```json
{
  "temperature": { "mode": "VALUE", "value": 0.4 },
  "top_p": { "mode": "OMIT" }
}
```

- INHERIT / 未出现：普通参数继承上层，若上层也未配置则不发送；思考参数不继承渠道。
- VALUE：使用显式值，false、0、空数组都不同于未设置。
- OMIT：覆盖上层，并从请求中删除该字段。
- 点路径构建嵌套对象，例如 `generationConfig.temperature`。对象与点路径混用时，子字段优先；普通子字段省略会保留其他字段，继承会恢复渠道中的对应值。
- `extraBody` 支持服务扩展字段，但不得代替协议必需的结构。
- Anthropic 的 `max_tokens` 为必需的正整数：优先使用最终请求中的显式值，其次使用模型最大输出；两者都没有时，普通请求默认 1024，`thinking.type = enabled` 时默认使用思考预算加 1024。
- 手动开启 Anthropic 思考时，`budget_tokens` 必须是至少 1024 的整数，最终 `max_tokens` 必须严格大于预算。实际采用的显式上限或模型上限小于等于预算会报错，应用不会静默提高这些已设置的上限；`extraBody` 覆盖后的最终值同样校验。
- timeout/retry 等为客户端选项，不发送到模型请求体。
- 模型的协议、URL、Headers 和兼容选项可覆盖渠道。用途本身不是模型能力分类。

普通参数的 GUI 使用未设置、跟随服务、自定义值、不发送等选项表示以上三态，思考分组使用模型自己的「默认 / 修改」。预设建议值只作提示，不会自动启用。常用字段提供布尔、数字、选项等控件；额外字段可指定文本、整数、数字、布尔、JSON 对象或数组，对象和数组编辑时先验证 JSON 类型。

四协议参数目录来自各协议的实际请求支持面。配置元信息不会自动开启额外的会话功能，也不会用于判断模型是否能处理视觉或思考请求。

### 解答页的临时思考设置

每题解答的紧凑标题区显示当前模型和本次思考层级。标签记录本次请求经过协议编码、兼容设置处理后的思考参数；没有发送思考参数时简写为「默认」，其语义为服务端默认，并不代表应用知道服务端内部实际使用的思考强度。

点击思考胶囊打开紧凑的锚定浮层，不改变答案正文高度。蓝紫渐变离散滑杆选择深度，「默认」选择模型原来的思考参数；这些操作只更新草稿，点击「确认」才重试当前题当前模式。关闭浮层丢弃草稿，入口继续显示实际请求层级。没有单独的模型或还原按钮。「预算」关闭浮层后显示一行输入及「确认／取消」，填写后点击确认才发送。题目尚未识别完成或协议不能确定时，入口不开放。选项依据协议提供，不按模型名称猜测支持情况。

请求自动回退到其他模型或协议时，会关闭旧浮层并丢弃未提交的层级和预算；重新打开后使用当前实际模型的选项，保留原有阅读状态。

手动预算通常使用数字键盘；Gemini 使用可输入负号的文本键盘，以支持 -1。解答底栏随键盘避让。若答案窗已被拖小，进入预算编辑时暂时扩展到至少默认高度，退出编辑恢复用户设置的高度。

- 「默认」：清除本题当前模式的临时覆盖，恢复当前模型原来的全部思考配置（含摘要、展示偏好与 `extraBody` 等）。若模型原本没有显式思考参数，则按原配置发送，不额外开启思考。
- 选择强度或预算：替换强度、预算及对应启用模式，保留模型的 `reasoning.summary`、`thinking.display`、Gemini `includeThoughts` 和 Chat Completions `thinkingBudgets` 档位预算映射等辅助设置，包括 `extraBody` 和点路径中的配置。只影响当前题、当前模式，其他题目及另一模式不变。普通重试沿用临时设置，切换到其他模型或开始新截图后恢复模型设置。
- 参数预检失败时，错误显示在思考入口或预算输入下方，保留已有答案和正在运行的请求；更正后可重试。临时设置不修改模型、渠道或用途绑定，也不写入配置文件。

| 协议 | 临时强度 | 临时预算 |
|---|---|---|
| OpenAI Chat Completions | `none`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max` | 通过已有兼容设置转换强度，不提供独立预算输入 |
| OpenAI Responses | `none`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max` | 不提供独立预算输入 |
| Anthropic Messages | `low`、`medium`、`high`、`xhigh`、`max`，使用 adaptive 模式 | 至少 1024 的整数，使用 enabled 模式；与强度互斥，仍检查有效输出上限是否大于预算 |
| Gemini | `MINIMAL`、`LOW`、`MEDIUM`、`HIGH` | `-1` 动态、`0` 禁用或正整数；与强度互斥 |

解答页与模型详情使用同一协议参数目录。界面将 `none` 显示为「关闭」，`minimal` / `MINIMAL` 为「最低」，`low` / `LOW` 为「低」，`medium` / `MEDIUM` 为「中」，`high` / `HIGH` 为「高」，`xhigh` 为「很高」，`max` 为「最高」；请求仍使用表中的协议原值。

## 结构字段与变量

底层解析器兼容 pi 风格的 `providers` 结构。文件中的 `headers`、`compat`、`models` 和 `modelOverrides` 会保留，`modelOverrides` 最后应用；缺失的模型会转换为可编辑条目并显示提示。`reasoning`、`input` 等元数据不限制模型选择。

`$VAR` 和 `${VAR}` 映射到应用内变量；`$$` 与 `$!` 表示字面转义。不会执行 `!command`；订阅登录配置需要改为 API 凭据后才能使用。凭据引用在新设备上需重新填写。

## 本地与远程管理

本地配置集存放在应用私有目录，使用原子文件替换并保留上一版本；系统文件选择器用于导入/导出用户可管理的 JSON。默认备份不包含明文密钥，若明确选择包含凭据，请妥善保存导出文件。

从「我的 → 模型服务 → 配置文件」新建、复制、重命名和切换配置集。新建与复制完成后会切换到目标配置；删除当前配置集时先切换到另一项，最后一个配置集不能在 GUI 中删除。「恢复上一个版本」需确认。系统文件导入支持 UTF-8（含 BOM），当前限制为 2 MB。

「导出配置文件」保留用途与应用扩展，默认不包含密钥；显式选择包含密钥后，导出文件可包含明文凭据。默认导出的本机凭据引用不提供跨设备密钥迁移，新设备需要重新填写或映射变量。

悬浮球拖动位置属于设备本地设置，不写入或导出到渠道配置 JSON，切换配置集也不改变位置记忆。没有保存位置时，悬浮球位于屏幕右侧，球心距顶部约四分之三屏高（75%）；已有位置时，下次开启或进程重启后优先恢复，并在旋转屏幕或变更悬浮球大小后约束在屏幕可见范围内。

「配置文件 → 远程配置」通过 URL 获取文件，先预览，再合并或替换。刷新使用上次来源、本地版本和新远程版本进行三方比较；本地修改在冲突时优先。预览生成后若配置发生变化，必须重新预览。网络错误、坏 JSON 和未知协议不会更改当前有效配置；缺失变量会提示手动映射。

迁移兼容 ai_settings 的旧 API/OCR/fast/deep 键、default_channel 中间版本和 channels_json / usage_model_pools_json。迁移前加密保存旧设置；解析失败保留原始文件。

具体的界面、文件与真实协议验证步骤见 [手工验证](manual-verification.md)。
